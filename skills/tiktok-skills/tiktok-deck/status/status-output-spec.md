# 営業ステータス別・入力／出力仕様

## 共通原則

- 営業が資料名・ページ・分析項目を明示した場合、その指定を標準仕様より優先する。
- 既に添付・回答済みの情報は再質問しない。指定がなければ編集用PPTXと配布用PDFを出す。
取得条件（検索語・地域・取得時刻・表示順）は取得JSONに記録される。施策前後を比べる場合は同じ検索語・同じ条件で再取得すること。**ログイン状態は使わない**。
- 資料には取得日、検索語、対象件数、重複除外数、公式アカウント判定根拠を残す。
- 検索順位・露出シェアは取得時点のスナップショットであり、恒常的順位や因果を示さない。

## 複数ステータスを1資料へ統合する場合

- `123`、`234`、`1と5と3`等、指定された任意の集合を1資料にできる。「別々」「それぞれ」の明示がなければ、1つの資料を求める依頼は統合版にする。
- 順序指定がなければ、選択した章だけを `①現状 → ⑤競合差 → ⑥クチコミ → ②方向性 → ③実行案 → ④結果` の順に並べる。順序が明示された場合は従う。
  （クチコミ章＝REVIEWS は、競合差の直後・方向性の直前に置く。「証拠→判断→実行」の流れにするため。生成コードでもこの順で出力する。）
- 表紙と案件情報 → 全体結論 → 選択された章 → 次の行動、を基本骨格とする。表紙、全体要約、調査方法、共通証拠、制約、CTAは重複させない。
- 必須入力は各章の必須入力の和集合を重複除外して使う。同一の取得データを複数章で再提出させず、同一の実画面を再掲する場合は章ごとに結論を変えるのではなく相互参照する。
- ④を含む場合は、他章の入力がそろっていても施策前基準データの有無を先に確認する。基準がなければ通常の統合資料を「施策前後比較あり」として生成しない。
- ⑤は単独指定時には独立資料、複数指定時には競合差から方向性／実行案へつなぐ章として統合する。

## 1｜初訪資料

**目的**：検索上の現状を短時間で示し、分析への信頼を得る。

**必須入力**

1. 顧客ブランド名
2. 顧客公式TikTok URLまたは正確なアカウントID
3. 一般キーワード（1つ以上）
4. 一般キーワードの検索結果（01-acquireで取得）
5. ブランド名の検索結果（01-acquireで取得）

**任意入力**：対象商品・公式商品URL、競合名と検索結果、商談背景、相手部署、希望ページ数、関連公式アカウント一覧。

**標準出力（6〜10ページ）**

1. 今どこで見え、どこで見えていないか
2. 一般キーワード検索の露出構成・露出シェア
3. **一般キーワード検索での顧客公式アカウント露出**
4. **ブランド名検索での顧客公式アカウント露出**
5. ブランド名検索における公式投稿／第三者投稿の構成
6. 上位投稿で使われるハッシュタグと #PR 表記あり／なし
7. 上位の代表投稿と分かりやすい共通点
8. 顧客の機会と次回詳しく確認できる内容

露出シェアは「上位100件中、公式8件＝8.0%」のように分母・分子を併記する。2検索は混ぜず別々に示す。指定がなければ秒単位台本や上位10本全件解剖は含めない。

**注意**：公式URL／IDで公式判定する。ブランド名検索の第三者投稿を「自社投稿上位」と書かない。検索ごとの取得件数が違う場合は母数を明示する。

## 2｜具体提案資料

**目的**：上位投稿の共通点と保存される理由から、次に取り組む方向を合意する。

**必須入力**：顧客ブランド、対象商品／カテゴリ、一般キーワード、一般検索結果、ブランド検索結果、提案目的（検索露出・認知・保存・来店・購入等）。

**任意入力**：競合名と検索結果、公式TikTok／商品URL、制作本数・尺・出演可否・予算・制約、過去投稿URLと実績。

**標準出力（10〜16ページ）**

1. 現状と提案結論
2. 顧客・競合・一般検索で露出する投稿の比較
3. 各軸4〜5本の実画面、再生数、保存数、保存率
4. 冒頭→中盤→終盤の流れの違い
5. 上位群で多い表現・キラー演出の仮説
6. 顧客が取り入れる点／避ける点
7. 推奨する投稿方向3案と優先順位、検証指標

**注意**：保存数だけで評価せず再生母数、保存率、購入・来店とのつながりを併記する。5,000再生未満の保存率は参考値。共通点は相関・仮説であり上位表示の原因と断定しない。

## 3｜構成提案資料

**目的**：合意した方向を、制作担当が実行できる企画・構成・台本へ変換する。

**必須入力**：顧客ブランド・商品・公式商品URL、採用テーマ／訴求軸、目的とCTA、尺・本数・掲載先、必須／禁止表現・ブランドトーン、②の確定資料（計測結果）。

**任意入力**：ターゲット、利用シーン、出演者、ロケ地、使用素材、撮影条件、法務・薬機・景表上の確認事項、音源・顔出し可否、過去の承認／否認構成。

**標準出力（10〜20ページ）**

1. 構成方針と上位投稿から採用した根拠
2. 投稿企画3案（指定があれば指定数）
3. 各案のフック、展開、商品提示、CTA
4. 秒数入り構成表／台本
5. 画面、テロップ、音声、必要素材、撮影カット
6. 実画面と顧客向けに置き換える箇所
7. A/Bテスト案、評価指標、制作前確認事項

**注意**：実在投稿をそのまま複製しない。商品・法的表現を推測しない。データで確認した事実とAIの仮説を分ける。

## 4｜レポート資料

**目的**：施策前後の検索露出と自社投稿結果を検証し、次の改善を決める。

**施策前に必ず保存**

1. 一般キーワードの検索結果（01-acquireで取得）
2. ブランド名の検索結果（01-acquireで取得）
3. 公式アカウントの投稿一覧と主要指標
4. 取得日時、端末／地域／取得条件、取得件数
5. 対象投稿がまだない場合はその事実

施策開始前に基準データがなければ、レポート生成へ進まず「効果比較のため、開始前に上記を取得してください」と明示して取得手順を返す。

**生成時の必須入力**：施策名・目的・対象／比較期間、施策前基準、同条件の施策後検索結果、対象自社投稿URL、投稿別の再生・いいね・コメント・共有・保存、投稿日・目的・PR表記情報。

**任意入力**：視聴維持・完視聴・プロフィール遷移・クリック・購買／来店、媒体費・制作費、競合同期間データ、キャンペーン・在庫・価格変更等。

**標準出力（10〜18ページ）**

1. 結論と次の判断
2. 施策前後の検索露出
3. 一般／ブランド検索での公式アカウント露出変化
4. 自社投稿別成果と全体集計
5. #PR表記あり／なしの差
6. 成果が高かった投稿の構成・訴求・保存要素
7. 未達項目と考えられる要因
8. 継続・修正・次回テスト

標準は検索露出と自社投稿結果の両方。営業が片方だけと明示した場合は指定範囲に絞る。

**基準なしで開始済みの場合**：後取得値を施策前と偽らない。明示希望時だけ施策後の現状レポートを暫定生成し、「基準がなく増減・効果は判定不可」と記す。その時点の値を次回基準として保存する。

**注意**：条件・母数が違う前後比較には注意表示。検索露出変化と投稿施策の因果を断定しない。媒体指標と売上・来店を混同しない。

## 5｜競合差再提案資料

**目的**：自社と競合の露出、訴求、キーワード、保存、構成差から未開拓機会を示す。

**必須入力**：顧客ブランド・商品・公式商品URL、競合1社以上、一般／第一想起キーワード、顧客・各競合・一般検索結果、再提案の背景と今回決めたいこと。

**任意入力**：各社公式TikTok、過去提案・却下理由・投稿実績、予算・制作条件・優先商品、比較語と表記ゆれ。

**標準出力（12〜20ページ）**

1. 再提案の結論と露出差
2. 第一想起語の登場率、1本平均登場回数、接点経路
3. #PR表記あり／なし比較
4. 各社4〜5本の実画面、再生数、保存数、保存率
5. 冒頭・中盤・終盤とキラー演出の差
6. 競合／自社の強み、不足、未開拓領域
7. 再提案3案、優先順位、検証方法

⑤だけを指定された場合は**独立資料**。他のステータスと同時指定された場合は、営業の依頼どおり同じ資料へ統合できる。

**注意**：検索軸の件数を揃え、揃わなければ率と母数を併記する。「競合が実施していない」ではなく「今回の取得範囲では未確認」と書く。差分の事実、仮説、提案を分ける。

## 指定された部分資料

「比較表だけ」「各社サムネページだけ」「PDFのみ」等が明示されたら、標準構成を強制せず指定物を作る。ただし対象検索語、取得日、母数、指標定義、出典リンク、データ制約、事実／推測の区別は省かない。
