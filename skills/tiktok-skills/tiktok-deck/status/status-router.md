# 営業ステータス・ルーター仕様

## 目的

営業担当者の自然文を読み、必要な資料を次の5種類へ振り分ける。営業担当者に番号選択を強制しない。相談文に作りたい資料・載せたい内容が明記されている場合は、その明示指示を最優先する。

| ID | 営業ステータス | 資料の主目的 |
|---|---|---|
| 1 | 初訪 | 現状を短時間で示し、分析の信頼を得る |
| 2 | 具体提案 | 検索上位の傾向から、取り組む方向性を合意する |
| 3 | 構成提案 | 合意した方向を投稿企画・構成・台本へ落とす |
| 4 | レポート | 施策前後と自社投稿の結果を検証し、次の改善を決める |
| 5 | 競合差再提案 | 自社と競合の差・空白を示し、新しい提案を作る |

①〜⑤は任意の部分集合で指定できる。`123`、`234`、`1と5と3`、`①⑤③`はいずれも有効。複数ステータスを「入れて」「まとめて」「1つの資料で」と依頼された場合は、原則として1つの統合資料にする。⑤は単独指定時だけ独立資料とする。

## 判定の優先順位

上から順に適用する。

1. **明示された成果物・掲載内容**
   - 「初訪用を作って」「上位動画4本の比較だけ出して」「この3項目を10ページで」など、作りたいものが明確ならその通りに出す。
   - 5分類はテンプレート選択と不足情報整理の補助にのみ使い、明示指示を削除・置換しない。
   - PDF/PPTX、動画本数、ページ数、「不要」「除外」も作成条件として保持する。否定された項目をキーワード一致だけで追加しない。
2. **明示された営業ステータス**
   - 掲載内容の細かな指定がなく「③構成提案を作って」と言われた場合は③の標準仕様を使う。
   - 複数番号、複数名称、番号と名称の混在はすべて保持する。数字列は「資料」「ステータス」「章」「①〜⑤」等の文脈がある場合だけ分解し、`135ページ`、日付、金額等をステータス指定と誤認しない。
3. **会話の目的と依頼動詞**
   - ステータス指定がないときだけ、下記の判定規則で自動分類する。
4. **会話履歴と添付資料**
   - 現在の依頼文だけで不明なとき、直前の会話・添付資料・既存資料を補助根拠にする。

### 明示指示が競合する場合

- 「初訪用だが、秒単位の台本を3本作って」のような依頼では、**成果物の具体性が勝つ**。③相当の制作物を含め、判定欄には「初訪用途／指定内容は構成提案相当」と記録する。
- 「①と⑤と③を入れて資料を出して」は①・⑤・③を1資料へ統合する。「①と⑤を別々に」は2資料にする。
- 「○○だけ」と言われた場合、標準ページを勝手に足さない。分析上必要な注記・出典・制約だけは残す。

## 複数ステータスの統合規則

1. 明示されたステータス集合を欠落させない。
2. 「別々」「それぞれ」「各資料」と明示された場合だけ分割する。それ以外で1つの資料作成を求められた場合は統合する。
3. 章順が明示されていればその順を保持する。順序指定がなければ、選択集合を `①現状 → ⑤競合差 → ②方向性 → ③実行案 → ④結果` の順に並べる。
4. 表紙、全体要約、調査条件／方法、共通証拠、制約、CTAは1回だけ置く。各章で同じ説明を繰り返さない。
5. 必須入力は選択ステータスの和集合を作り、項目名と受領値で重複除外する。受領済み情報を再質問しない。
6. ④を1つでも含む場合は施策前基準データを必須とし、不足時は通常の生成を止める。他章だけの暫定版を作るのは営業が明示的に希望した場合に限る。
7. ⑤は単独なら独立資料、他ステータスと同時指定なら統合可能とする。

## 自動分類規則

### 1｜初訪

次の意図が中心なら①。

- 初めて会う、休眠顧客への再接触、まず興味を持ってもらう
- 現状把握、検索に出ているか、一般検索でどれくらい見えるか
- 顧客公式アカウントの検索露出を確認したい
- 短く分かりやすい資料で分析力への信頼を得たい

①の公式アカウント露出は、必ず次の両方を扱う。

1. 一般キーワード検索に顧客公式アカウントの投稿が出ているか
2. ブランド名検索に顧客公式アカウントの投稿が出ているか

### 2｜具体提案

次の意図が中心なら②。

- 何をテーマに投稿すべきか、どの勝ちパターンを採用すべきか決めたい
- 上位動画の共通点、保存される要素、キラー演出を提案にしたい
- 顧客と企画の方向性を合意したいが、台本制作までは求めていない

### 3｜構成提案

次の意図が中心なら③。

- 投稿案、絵コンテ、秒単位の構成、台本、撮影指示が欲しい
- 冒頭・中盤・終盤、テロップ、音声、CTAを具体化したい
- 制作チームへそのまま渡せる内容が必要

### 4｜レポート

次の意図が中心なら④。

- 実施済み施策の結果、前後比較、月次報告、振り返り
- 検索露出が増えたか、自社投稿が成果を出したか確認したい
- 次月の改善や継続判断につなげたい

④の標準レポートは「検索露出」と「自社投稿結果」の両方を扱う。**施策開始前の基準データが必要**。開始前で基準データがなければ資料生成を止め、先に同条件で検索結果と自社アカウント指標を取得するよう明示する。

### 5｜競合差再提案

次の意図が中心なら⑤。

- 既存提案が進まない、競合との差から新しい切り口が欲しい
- 自社に足りない訴求、競合が取れている検索・保存・演出を示したい
- 未開拓テーマや参入余地を根拠に再提案したい

## 複数ステータスに該当する場合

- 営業が欲しい成果物を明記している：その成果物を優先する。
- 複数ステータス番号または名称が明記されている：すべて保持し、上記の統合規則を適用する。
- ステータス指定がなく複数目的がある：会話上の「次に決めたいこと」に最も近いものを主判定にし、明確に必要な章だけを追加する。
- 複数の独立資料を明確に依頼された：指定数の資料を生成する。
- 迷いがあっても資料内容が同じなら、分類確認だけのために止めない。
- 分類によって必要データや成果物が大きく変わる場合だけ、選択肢を1問で確認する。

## 確信度と確認の要否

内部では `high` / `medium` / `low` を保持する。

- `high`：成果物または営業ステータスが明示されている
- `medium`：目的と依頼動詞から1種類に絞れる
- `low`：前後比較と企画制作など、必要データが異なる複数目的が同程度に含まれる

`low`でも、明示された成果物があればそのまま進める。追加質問は完成物を左右する重大な曖昧さだけに限定する。

## 直接依頼の扱い例

| 営業の依頼 | Agentの処理 |
|---|---|
| 「初訪用。『コンビニ』検索の露出シェアと、セブン公式が一般検索・ブランド検索の両方に出ているかを資料にして」 | ①。指定内容をそのまま予定成果物にし、不足データだけ聞く |
| 「番号は分からない。上位動画の共通点とキラー演出を4本ずつ比較して提案したい」 | ②。分類理由を示すが、4本ずつという指定を優先する |
| 「③を作って。15秒台本を3案、価格訴求案は不要」 | ③。価格訴求ページを足さず、15秒台本3案を作る |
| 「今月の投稿結果と検索順位を先月比でレポートにして」 | ④。施策前データと今月データ、自社投稿指標を確認する |
| 「来月施策を始める。まだ検索データは取っていない」 | ④の事前計測として止め、開始前の検索結果・自社投稿指標の取得を案内する |
| 「競合との差を見て再提案資料を単独で作って」 | ⑤。独立資料を生成し、①〜④へ自動結合しない |
| 「1と5と3を入れて、1つの資料を出して」 | ①・⑤・③を1資料へ統合。章指定がなければ①→⑤→③。共通ページと必須入力を重複させない |
| 「234をまとめて作って」 | ②・③・④を1資料へ統合。ただし④の施策前基準がなければ生成前に取得を案内する |
| 「①⑤③をそれぞれ作って」 | ①・⑤・③の3資料。独立指定を保持する |
| 「135ページで作って」 | ステータス指定ではなくページ数として扱う。文脈が曖昧なら1問だけ確認する |
| 「ファミマとローソンの保存数比較ページだけPDFで」 | 明示成果物優先。分類に合わせて余計な標準ページを追加しない |
| 「キラー演出は不要。露出シェアだけ」 | キラー演出を除外し、露出シェアだけを作る |

## 禁止事項

- 営業担当者に、毎回①〜⑤の番号を選ばせる
- 明示された掲載内容を、分類テンプレートの都合で省く
- すでに会話・添付ファイルにある情報をもう一度聞く
- 複数指定されたステータスの一部を落とす、または「別々」の明示なしに勝手に分割する
- ④で施策前データがないのに、施策効果や増減を断定する
- 分類確認のためだけに、生成可能な依頼を停止する
