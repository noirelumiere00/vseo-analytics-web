# TikTok競合分析 → 提案資料作成スキル ガイド

営業がTikTokの検索面データから、クライアント提案用の資料（PPTX）を作るための一連のスキルです。
本ガイドは「①概要」「②モジュール詳細」「③資料タイプ別仕様」で構成しています。

> 章の並び順を、提案の自然な流れに沿って整理しました（2026-09 改修）。
> **現状把握＋競合差 → 市場の空白地帯 → クチコミ → 方向性＋実行案 → 締め**

---

## ① 概要

### 何をするスキルか
- TikTokの検索結果を「実際に画面に出ている順番のまま」取得（ログイン不要・無料・回数制限なし）
- 自社／競合／市場キーワードを同じ定義で定量比較
- 上位動画を実際にダウンロードし、AIがコマ単位で構成を解剖
- EC（楽天・Yahoo!・@cosme 等）の口コミを収集・集計
- これらを営業ステータス別のPPTXに整形し、提出前に機械検査（前検）

### 4モジュールのパイプライン
```
tiktok-intake（受付）    依頼を受け、必要情報を確定
      ↓
tiktok-acquire（取得）   検索面データ・動画実体を取得
      ↓
tiktok-analyze（計測）   キーワード登場率・勝ちパターンを計測
      ↓
tiktok-deck（資料化）    ステータス別にPPTXを生成 ← 本体
```

補助：`review-scraper`（クチコミ収集）… 楽天/Yahoo!/@cosme の口コミを集めて集計。tiktok-deck の `# REVIEWS` 章の入力になる。標準ライブラリのみで動作（pip不要）。

### 資料の章の流れ（改修後の並び）
統合資料（複数ステータスを1本化）にすると、次の順序で並びます。

| 順 | パート | 対応ステージ | 中身 |
|---|---|---|---|
| 1 | **PART1 検索面の実態** | 現状把握＋競合差 | 誰が出ているか／PR比／クラスタ／商品／上位投稿 |
| 2 | **PART2 検索ワードの露出実態** | 競合差（市場の空白地帯） | カテゴリ名検索での上位・保存・自社の不在 |
| 3 | **REVIEWS 口コミ** | クチコミ | 件数・好意/離脱理由・評価の出自・打ち手 |
| 4 | **PART3 動画の構成解剖** | 方向性＋実行案 | 勝ちパターン・実動画のコマ解剖・台本方向 |
| 5 | **SUMMARY 総括** | 締め | 勝ちパターン総括 → KEEP/IMPROVE/TRY |

> 「証拠（現状・競合・顧客の声）→ 判断（方向性）→ 実行（構成案）」の順に読ませる設計です。

### 守っていること
- TikTokにログインしない／CAPTCHAを突破しない／UA・IP偽装をしない
- 見ていないコマを「見た」と書かない（AIが実際にコマを開いて8軸で記述）
- 未計測を「0」と書かない（measured／unmeasured／not_applicable を区別）
- 提出前に前検（版面崩れ・数値矛盾・画像とキャプションのズレ）を通す

## ② モジュール詳細

### tiktok-intake（受付）
- 役割：営業の依頼文または依頼票を受け、資料タイプ（型）を推定し、必要情報を確定
- 特徴：質問を最小化。検索キーワードは公式サイトから候補を作る。競合はクライアント確認前提でも着手可
- 主なスクリプト：`intake_form.py`（型推定・3分類）、`gaps.py`（不足→次の一手）

### tiktok-acquire（取得）
- 役割：検索面データと動画実体の取得
- 特徴：内部APIのレスポンスを傍受して検索表示順のまま取得。動画は埋め込みページ経由で確実に取得
- 取れるもの：検索表示順・再生/いいね/コメント/シェア/**保存数**・投稿日・尺・本文・ハッシュタグ・音源・**PRフラグ(isAd)**・フォロワー数・認証バッジ
- 主なスクリプト：`search.mjs`（search/comments/download/fetch）、`tiktok_report.py`（定型レポート）

### tiktok-analyze（計測）
- 役割：取得済み媒体から数字を作る
- 特徴：4経路（本文／ハッシュタグ／テロップ／音声）の登場率、話題クラスタ、上位の勝ちパターン
- 注意：テロップはAIがフレームを実見して取り込む（機械OCRは使わない）
- 主なスクリプト：`build_dataset.py`（データセット構築）、`measure_keywords.py`、`rank_patterns.py`

### review-scraper（クチコミ収集）
- 役割：EC/口コミサイトのレビューを集めてCSV・JSONL・集計サマリーにする
- 対応：楽天市場／Yahoo!ショッピング／@cosme（Amazon・LIPS・Qoo10 は自動アクセス拒否のため対象外）
- 特徴：標準ライブラリのみで動作（pip不要）。集計結果を tiktok-deck の `# REVIEWS` 章へ流し込む
- 主なスクリプト：`scripts/collect.py`、`scripts/sites/{rakuten,yahoo,cosme}.py`

### tiktok-deck（資料化）※本体・今回改修
- 役割：ステータス別にPPTXを生成
- 工程：
  1. `case.json`（誰を・何で検索したか。数値は書かない）
  2. `tools/extract_frames.py`（動画→コマ抽出、contact.jpgで全体把握）
  3. **AI目視**：コマを実際に開き、8軸（フック／視覚演出／テロップ／価格/スペック／商品識別／CTA／勝因仮説／本質1行）で記述
  4. `tools/build_input_md.py`（機械欄）＋ `authored.md`（散文）→ `tools/merge_authored.py` → `INPUT.md`
  5. `node src/generate.js --mode <ステータス>`（章はステータスで決まる。複数指定で統合＝`--mode "初訪,具体提案"`）
  6. 前検：`tools/preflight.py`（版面崩れ・数値矛盾）、`tools/verify_assets.py`（画像とキャプションのズレ）
- 生成の章順（改修点）：`generate.js` 内で **REVIEWS（口コミ）章を PART3（動画構成）の前** に出すよう変更
- 口コミ章の入力：`INPUT.md` の `# REVIEWS` セクション
  - `## SURVEY`：`media`／`method`／`asymmetry_note`／`scale_note`／**`media_a_label`・`media_b_label`・`media_c_label`**（評価出自表の媒体名。既定は @cosme / LIPS。食品等では「楽天」「Yahoo!」等に差し替え可）
  - `## BRAND REVIEWS` → `### BRAND`：`reviews_read`／`cosme_rating`(=媒体A評価)／`cosme_count`／`lips_rating`(=媒体B評価)／`lips_count`／`lips_pr_ratio`(=媒体C列)／`#### Love`・`#### Churn`（理由｜言及数）・`#### Quotes`（原文｜出典）
  - `## CROSS`：`love_patterns`／`churn_patterns`／`love_conclusion`／`churn_conclusion`
  - `## ACTIONS`：離脱理由｜対応する打ち手

#### 今回の改修まとめ（tiktok-deck）
| 変更 | 内容 |
|---|---|
| 章順の変更 | 口コミ（REVIEWS）を動画構成解剖（PART3）の**前**へ移動 |
| 不具合修正 | 口コミ「自社深掘り(R4)」で `find` の引数取り違えにより落ちる問題を修正 |
| 表示改善 | 比較表がブランド数を超えて空行を水増しし `[DATA NOT PROVIDED]` が並ぶ問題を、実ブランド数までに抑制 |
| 表示改善 | 好意/離脱理由が3件未満のとき、空欄を `[DATA NOT PROVIDED]` ではなく「—」で表示 |
| 汎用化 | 評価出自表(R5)の媒体名を `SURVEY` から差し替え可能に（既定 @cosme/LIPS、食品等で楽天/Yahoo!に対応） |

## ③ 資料タイプ別仕様

`node src/generate.js --mode <型>` の `<型>` で章が決まります。複数指定で1本に統合（章は和集合、上記の並び順）。

### 型と含まれる章
| 章 | 初訪 | 具体提案 | 構成提案 | 競合差再提案 | レポート |
|---|:---:|:---:|:---:|:---:|:---:|
| Q1 誰が / Q2 PR比 | ○ | ○ | ✗ | ○ | ○ |
| Q3 クラスタ / Q4 商品 | ✗ | ○ | ✗ | ○ | ○ |
| Q5 上位投稿 | ✗ | ○ | ○ | ○ | ○ |
| Q6 検索ワード面 | Headのみ | ○ | ✗ | ○ | ○ |
| Q7/Q8 動画の構成解剖 | ✗ | ○ | ○ | ✗ | ✗ |
| REVIEWS 口コミ | ✗ | ○ | ✗ | ○ | ✗ |
| 他プラットフォーム | ✗ | ○ | ✗ | ○ | ✗ |
| 勝ちパターン総括 | ✗ | ○ | ○ | ✗ | ✗ |
| 施策前後比較 | ✗ | ✗ | ✗ | ✗ | ○（基準必須） |

### 各型の目的と標準枚数
- **初訪（quick）**：検索上の現状を短時間で示し、分析への信頼を得る。6〜10ページ
- **具体提案（deep）**：上位の共通点と保存理由から次の方向を合意する。10〜16ページ
- **構成提案**：合意した方向を、制作が実行できる企画・構成・台本へ変換。10〜20ページ
- **競合差再提案**：競合との差だけを定量比較し、差別化の打ち手を示す。単独/統合どちらも可
- **レポート**：施策前後の検索露出と自社投稿結果を検証。**施策前の基準データが無いと生成不可**

### 呼び出し例
```bash
# 単体
node src/generate.js --mode 初訪
node src/generate.js --mode 競合差再提案

# 1本に統合（改修後の並び：現状+競合差 → 市場空白 → 口コミ → 方向性+実行案 → 締め）
node src/generate.js --mode "初訪,競合差再提案,具体提案,構成提案"

# 別名：quick=初訪 / deep=具体提案。PDFが要る環境では --pdf（要 LibreOffice）
```

### 注意
- 露出シェアは「上位◯件中 公式△件＝△%」と分母・分子を併記。2つの検索は混ぜない
- 保存数だけで評価せず、再生母数・保存率・購買/来店とのつながりを併記
- 実在投稿をそのまま複製しない。データで確認した事実とAIの仮説（示唆）を分ける
- レポートは後から取った値を「施策前」と偽らない
